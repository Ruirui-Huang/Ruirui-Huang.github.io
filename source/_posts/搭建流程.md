## 简介：GitHub Pages ＆ Hexo

### GitHub Pages 是什么？

GitHub Pages 是 GitHub 官方提供的免费静态站点托管服务，把公开仓库直接发布成网站，支持 HTTPS、免费、无停服风险——非常适合个人博客。

### Hexo 是什么？

Hexo 是基于 Node.js 的静态博客框架，Markdown 写作，一条命令生成静态页面并部署到 GitHub Pages。**部署产物（master 分支）与源文件（source 分支）分开管理**是本博客的核心架构。

## 一、从零搭建（新电脑 / 新博客）

### 1.1 环境准备

1. 注册 [GitHub](https://github.com/) 账号，新建仓库 `<用户名>.github.io`（公开仓库，**开启 Issues**，供 Utterances 使用）；
2. 安装 [Git for Windows](https://git-scm.com/download/win) 与 [Node.js LTS](https://nodejs.org/)；
3. 配置全局 git 身份（换新电脑后必做，否则部署会报 `unable to auto-detect email address`）：

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"
# 验证
git config --global user.name
git config --global user.email
```

> `user.email` 建议填 GitHub 绑定邮箱；不想暴露真实邮箱，可在 GitHub Settings → Emails 里查你的专属 `xxx@users.noreply.github.com`。

### 1.2 初始化站点

```bash
# 在目标目录执行（本博客在 D:\Code\blog）
hexo init blog
cd blog
npm install
```

> `hexo init` 生成 `source/_posts/`、`_config.yml`、`package.json` 等基础结构。

### 1.3 安装主题与插件

```bash
# 安装 NexT 主题（npm 装好后要复制到 themes/next 才会生效）
npm install hexo-theme-next@8.29.0
mkdir themes
Copy-Item -Recurse node_modules/hexo-theme-next themes/next

# 渲染器与部署插件
npm install hexo-renderer-marked hexo-renderer-stylus hexo-server hexo-deployer-git

# 可选：本地搜索 / RSS / 站点地图
npm install hexo-generator-searchdb hexo-generator-feed hexo-generator-sitemap
```

> **重要**：确认 `package.json` 里包含 `"hexo": { "version": "7.3.0" }` 字段，缺了它 Hexo 不会加载任何外部插件（生成 0 篇文章），详见问题集合。

### 1.4 站点配置 `_config.yml`

```yaml
title: HuangR's Blog
subtitle: 记录世界，记录你！
author: 黄锐
language: zh-CN          # NexT 8 无 zh-Hans，必须用 zh-CN
timezone: Asia/Shanghai
url: https://你的用户名.github.io/
theme: next

deploy:
  type: git
  repo: https://github.com/你的用户名/你的用户名.github.io.git
  branch: master
```

### 1.6 首次发布

```bash
hexo clean
hexo g          # 生成
hexo s          # 本地预览 http://localhost:4000，确认无误后
hexo d          # 部署（首次会弹出 GitHub 登录授权）
```

> 部署后网站 1~2 分钟更新属正常，无需重复操作。

## 二、日常写作、发布与备份

```bash
hexo new "文章标题"        # 新建（标题含空格必须加引号）
# 编辑 source/_posts/标题.md，填写 front-matter（title/date/categories/tags）后写正文

hexo g && hexo s          # 本地预览确认
hexo d                    # 发布到线上
```

**源文件备份（血泪教训，必做）**：本博客曾因旧电脑报废、源文件只存本地而全部丢失。源文件必须推送到 GitHub 的 `source` 分支（与部署产物 `master` 分开）：

```bash
git init
git add .
git commit -m "博客源文件"
git remote add origin https://github.com/你的用户名/你的用户名.github.io.git
git push -u origin HEAD:source
```

之后每次写完文章，发布 + 备份一起做：

```bash
hexo d
git add . && git commit -m "更新文章：xxx" && git push origin HEAD:source
```

换电脑恢复：`git clone -b source <仓库>` → `npm install` → 按需 `npm install <主题与插件>` → 开写。**源文件在，博客就丢不了。**

## 三、旧站迁移 / 恢复（旧电脑报废场景）

适用：旧电脑已不可用，但 GitHub 线上仓库（部署产物）还在。**仓库里只有编译产物、没有源文件**，需要从静态站反推恢复。以下为实测完整流程：

### 3.1 下载旧仓库

GitHub 直连不稳，走镜像加速（在原始链接前加 `https://ghfast.top/`）：

```bash
curl.exe -L -o blog.tar.gz "https://ghfast.top/https://github.com/你的用户名/你的用户名.github.io/archive/refs/heads/master.tar.gz"
```

> PowerShell 中 `curl` 是 `Invoke-WebRequest` 的别名，参数不兼容，**必须写 `curl.exe`**。

### 3.2 解压

Windows 自带 `tar` 解压中文文件名会乱码，改用 Python：

```python
import tarfile
with tarfile.open('blog.tar.gz', 'r:gz') as t:
    t.extractall('blog-static')   # 文件名编码正常
```

### 3.3 提取文章清单

旧站里能拿到：`index.html`（首页）、`archives/`（归档）、`categories/`、`tags/`、各年份文章目录、`atom.xml`（含全部文章元数据）、`search.xml`。

- **元数据**（标题/日期/分类/标签/摘要）：解析 `atom.xml`（UTF-8，注意 `<content>` 里是 HTML 转义）；
- **正文**：`<!-- more -->` 之后的内容在 atom 里只有截断摘要，**完整正文要从文章页 `<div class="post-body">` 里提取**（含代码块、图片、PDF 嵌入）。

### 3.4 HTML → Markdown 转换要点

用 Python（BeautifulSoup 或正则）逐篇转换，重点处理：

| 原站元素 | 转换规则 |
| --- | --- |
| `figure.highlight` 代码块 | 按 `span.line` 还原行内容，**去掉嵌套的 class span 干扰**，缩进按行首空格保留 |
| 标题/段落/列表/表格/引用 | 转对应 Markdown 语法 |
| 图片 `<img>` | 保留原路径（`/2018/02/05/xxx/title.jpg` 这类文章资源目录） |
| `<embed>`（PDF） | 保留为 HTML 标签（浏览器端 PDF 阅读器） |
| `<!-- more -->` | 保留为摘要截断标记 |
| HTML 实体 | `&gt;`/`&amp;` 等要解码回原字符 |

### 3.5 资源搬运清单

| 资源 | 目标位置（新站） |
| --- | --- |
| 文章图片 | 按原 URL 路径放 `source/`（如 `source/2018/02/05/搭建流程/`） |
| PDF 附件 | `source/pdf/` |
| 自定义头像/背景/打赏码 | `source/images/` |
| about 页 | `source/about/index.md` |

### 3.6 重建与部署

按本文「一」搭好新站 → 把转换好的 `.md` 放入 `source/_posts/` → `hexo g` 逐篇核对渲染（重点：代码高亮、图片、PDF、TOC）→ 按「二」配置备份 → `hexo d` 部署。**若线上仓库已有历史提交，部署会被拒，需强制推送**（见问题集合）。

## 四、问题集合（全部实测）

### GitHub 直连超时 / TLS 报错（schannel CRYPT_E_NO_REVOCATION_CHECK）

国内访问 GitHub 不稳定，clone/curl 常超时或报 TLS 错。**解决**：走镜像 `https://ghfast.top/` 前缀加速下载。

### hexo 8.x 命令无效（只显示 usage）/ 建议用 7.x

Hexo 8 存在兼容问题（console 命令空白）。**解决**：固定 7.3.0：

```bash
npm install hexo@7.3.0
```

### package.json 缺 hexo 字段导致生成 0 篇文章

缺 `"hexo": { "version": "x.x.x" }` 时 Hexo 认为站点未初始化，不加载任何插件（渲染器/生成器失效）。**解决**：补上该字段并重新 `npm install`。

### 主题报 template not found: _layout.njk

外部 `hexo-renderer-nunjucks` 破坏主题模板相对路径解析。**解决**：卸载，用 Hexo 7 内置 nunjucks：

```bash
npm uninstall hexo-renderer-nunjucks
```

### 代码高亮主题失效

highlight.js 11 已移除 `tomorrow-night`。**解决**：`codeblock.theme.dark` 用 `atom-one-dark`。

### 页面语言变德语（Suche/Erstellt）

语言代码不匹配导致回退默认语言。NexT 8 只有 `zh-CN.yml`。**解决**：`language: zh-CN`。

### 部署报 unable to auto-detect email address

`.deploy_git` 子仓库读不到仓库级身份。**解决**：配置全局 git 身份（见 1.1）。

### Error: listen EADDRINUSE :::4000

```bash
netstat -ano | findstr "4000"   # 找到 PID
taskkill -PID 8976 -F           # 结束进程
```

### 部署被拒：! [rejected] master -> master (fetch first)

线上仓库有旧历史（如迁移场景），部署产物是整体替换，直接强制推送：

```bash
git -C .deploy_git push -u origin master --force
```

### Windows tar 解压中文乱码

用 Python `tarfile` 解压（见 3.2），或 PowerShell 指定编码后处理。

### Code 504: The app is archived（Valine 时代遗留，已过时）

老方案 Valine 依赖的 LeanCloud **2027-01-12 全面停服、数据销毁**，本站已迁移 Utterances。如旧站页面残留 Valine 凭据（appId/appKey），仅作历史存档即可，不再使用。

### GitHub Actions 构建时区导致文章路径跨天（差一天 404）

Hexo 生成文章路径用构建环境的**本地时区**解释 front-matter date。本机 UTC+8 与 Actions 默认 UTC 对午夜附近的 date（如 `2018-02-05 00:20:07`）会解析出**不同日期路径**（02-05 vs 02-04）。**解决**：workflow 的 Build step 设 `env: TZ: Asia/Shanghai`，与本地一致。

### source/404.html 被 Hexo 渲染成完整布局（带侧栏/评论区）

Hexo 7 会把 source 根的 .html 当页面渲染进主题布局（意外出现侧栏+评论区）。**解决**：404.html 顶部加 front-matter layout: false 即原样输出独立页。



## 五、LaTeX 学习笔记转博客正文（2026-09 实测）

场景：旧站部分文章以 `<embed src="/pdf/xxx.pdf">` 嵌入 PDF 展示，不优雅且移动端体验差。本站在 Overleaf 有 LaTeX 源（ctexart + morelull 模板），可整体转为 Markdown 正文，公式用 KaTeX 渲染。

> **2026-09 现状**：本站已尝试该方案并完成部署，但因排版与 PDF 原版仍有差距，已**回退为 PDF 嵌入显示**。本章完整保留转换方法、渲染器配置与全部坑点，如需再试可直接复用。

### 5.1 获取 Overleaf 源文件

- 项目页可浏览器下载 zip：**点击按钮后 `wait_for_download`**（`bu.download(zip链接)` 直下无效、按钮被浮层遮挡时用 JS 按 `[aria-label="Download .zip file"]` 点击）。
- zip 解压结构：`main.tex` + `demo.tex` + `morelull.sty`（自定义模板宏包）+ `imgs&code/`（图片）。

### 5.2 pandoc 转换（pypandoc-binary，pandoc 3.9）

```python
import pypandoc
md = pypandoc.convert_file('main.tex', 'markdown',
      extra_args=['--wrap=none', '--resource-path=<项目>/imgs&code'])
```

- **必须 `--resource-path` 指向图片目录**，否则图片引用丢失；图片实际在 `imgs&code/`（不是 images/）。
- pandoc 对 `\includegraphics[scale=...]` 输出**无尺寸的 `<img>`**；对 `[width=...]` 输出 `<img style="width:90%">`。都不是 markdown 图片语法。
- **预处理**：删除 `\usepackage{morelull}`（pandoc 解析该宏包会报错）；自定义环境 `{提醒}/{问题}/{特点}` → `{quote}`，否则内容丢失。
- **CRLF 坑**：pandoc 输出用 `\r\n`，行首正则全部失效，`clean()` 开头必须 `text.replace('\r\n', '\n')`。
- pandoc 会给标题加属性 `# 标题 {% raw %}{#id}{% endraw %}`——**hexo 会把它当模板注释解析报 FATAL**（expected end of comment），转换后必须删掉 ` {% raw %}{#xxx}{% endraw %}`。

### 5.3 渲染器：markdown-it + KaTeX（关键决策）

hexo-renderer-marked **会把 `$$...$$` 公式内容当普通 Markdown 解析**（`_` 变斜体、`&` 转义、公式被拆成段落/代码块），必须换渲染器：

```bash
npm un hexo-renderer-marked
npm i hexo-renderer-markdown-it @renbaoshuo/markdown-it-katex
```

`_config.yml`：

```yaml
markdown:
  render: { html: true, breaks: false, linkify: true }
  plugins:
    - name: '@renbaoshuo/markdown-it-katex'
      options: { throwOnError: false, strict: false }
```

主题 `_config.next.yml`（按页加载，仅含公式的文章加载）：

```yaml
math:
  every_page: false
  mathjax: { enable: false }
  katex: { enable: true, copy_tex: true }
```

文章 front-matter 必须加 **`mathjax: true`**（NexT 8 按页触发判断的就是这个字段，即使引擎是 KaTeX）。

### 5.4 排版坑清单（全部实测）

| 问题 | 处理 |
| --- | --- |
| 正文 section 变 h1，6 个大标题抢文章标题层级 | 转换后所有标题降一级（`#`→`##`） |
| 无尺寸大图溢出正文容器 | 所有 `<img>` 统一加 `max-width:100%;height:auto;display:block;margin:0 auto` |
| figure/figcaption 无样式 | 主题 `custom_file_path.style: source/_data/styles.styl` 加样式 |
| 块级公式不渲染 | `$$...$$` 必须独占段落（前后补空行） |
| `\text{$y=1$}` 嵌套 $ | 去除 \text 内层 $；`W_i_K` 双下标按语义改 `W_i^K` |
| `$^{\ref{xx}}$` 清理后残留孤立 `$$` | 先整删 `$^{\ref{xx}}$` 再删 `\ref{xx}` |
| pandoc 对齐式表格不渲染为 table | 转成 markdown 管道表格（或 `-t markdown+pipe_tables`） |
| 表格内 `$\geq$` 不渲染 | 直接替换为 Unicode `≥` |
| hexo 增量生成不检测 md 变化（0 files） | 转换后务必 `hexo clean && hexo g` |

### 5.5 验证与部署

```bash

npx hexo d                       # 部署 master

```

转换脚本复用：`convert_tex.py`（含以上全部修复，跑一遍重出 5 篇 md 并重拷图片），位于本站工具目录（见 README）。

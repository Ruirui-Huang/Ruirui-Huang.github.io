## 大模型训练

在训练大模型时，需要庞大的资源。单卡显存通常不能满足训练的需要，因此出现了大模型训练技术，其中典型的一种是DeepSpeed ZeRO

### DeepSpeed

DeepSpeed是微软开源的基于PyTorch的分布式框架，其支持了ZeRO, 3D-Parallelism, DeepSpeed-MoE, ZeRO-Infinity等训练策略。其中，DeepSpedd ZeRO支持切分优化器、梯度以及参数。

需配置 FlexibleRunner 的 strategy 和 optim_wrapper 参数：

- strategy：指定 type='DeepSpeedStrategy' 并配置参数

- optim_wrapper：指定 type='DeepSpeedOptimWrapper' 并配置参数

```python
from mmengine.runner._flexible_runner import FlexibleRunner

    # 指定 DeepSpeedStrategy 并配置参数
    strategy = dict(
        type='DeepSpeedStrategy',
        fp16=dict(
            enabled=True,
            fp16_master_weights_and_grads=False,
            loss_scale=0,
            loss_scale_window=500,
            hysteresis=2,
            min_loss_scale=1,
            initial_scale_power=15,
        ),
        inputs_to_half=[0],
        zero_optimization=dict(
            stage=3,
            allgather_partitions=True,
            reduce_scatter=True,
            allgather_bucket_size=50000000,
            reduce_bucket_size=50000000,
            overlap_comm=True,
            contiguous_gradients=True,
            cpu_offload=False),
    )
    
    # 指定 DeepSpeedOptimWrapper 并配置参数
    optim_wrapper = dict(
        type='DeepSpeedOptimWrapper',
        optimizer=dict(type='AdamW', lr=1e-3))
    
    # 初始化 FlexibleRunner
    runner = FlexibleRunner(
        model=MMResNet50(),
        work_dir='./work_dirs',
        strategy=strategy,
        train_dataloader=train_dataloader,
        optim_wrapper=optim_wrapper,
        param_scheduler=dict(type='LinearLR'),
        train_cfg=dict(by_epoch=True, max_epochs=10, val_interval=1),
        val_dataloader=val_dataloader,
        val_cfg=dict(),
        val_evaluator=dict(type=Accuracy))
    
    # 开始训练
    runner.train()
```

## 特征学习

衡量模型学到的特征好不好，有两种方式：

- Linear probe：把预训练好了的参数冻住，然后再训练一个分类头【可学习的空间较小】

- Fine tune：开放网络参数，直接端到端学习【往往比Linear probe的效果要好】

  > **CLIP为什么使用Linear probe？**
  >
  > 主要是因为：
  >
  > - CLIP的目的就是为了研究和数据集无关的与训练方式，如果下游任务的数据集足够大，且开放网络参数微调的话，很有可能是预训练的模型并不好，但是微调之后效果很好，**无法判断预训练参数到底好不好**
  >
  > - 下游任务不需要调参，不需要为不同的数据集设计超参数，流程正规

## CLIP的局限性

- CLIP很强，但是没有强到不可一世。如果加大数据和模型规模，CLIP的性能还能继续提高，但是计算量大概还需要$\times 1000$

- 细分类数据集效果不好，且无法处理一些抽象的任务

- out of distribution，CLIP也不好，比如MNIST

- 还是需要给定类别

- 数据用量太大，可以考虑自监督或伪标签

- 因为测试集是精心挑选的，无形带入了偏见

- 语言描述本身存在局限性

## Grouping Block

使用Gumbel-Softmax计算Group Tokens和图像段Tokens之间的相似性。每个图像段 Token被分配给与之最相似的一个Group Token。这个过程通过one-hot操作实现【**不是可微分的**】，确保每个图像段Token只属于一个Group。

## Image-Text Matching, ITM

ITM和ITC[10.2](ITC)很相似，区别在于ITC只通过encoder获取特征就判断是否对齐，而ITM让图像、文本特征经过多模态层之后再判断是否匹配。

对于ITM而言，判断负样本太简单了，如果简单的随机抽取样本作为负样本的话，模型训练效果不太好。作者在一个batch里，通过计算特征相似度，寻找一张图片中除它本身对应的文本之外相似度最高的文本作为负样本。这样就能构建一批hard negatives，从而提升训练难度。

## image encoder

利用mae预训练的vit，最低限度适应高分辨率的输入，该encoder在prompt encoder之前，对每张图像只运行一次。

输入$\left(c, h, w\right)$的图像，对图像进行缩放，按照长边缩放成1024，短边不够就pad，得到$\left(c, 1024, 1024\right)$的图像，经过image encoder，得到对图像16倍下采样的feature，大小为$\left(256, 64, 64\right)$。

## prompt encoder

分成2类：稀疏的(点，box，文本)，稠密的（mask）

- point：【点坐标调整加上0.5是为了向中心移动】映射到256维的向量，【填充处理，为了允许模型处理不同数量的点提示时保持输入一致】包含代表点位置的 positional encoding，加2个代表该点是前景/背景的可学习的embedding

- box：用一个embedding对表示

- 文本：通过CLIP模型进行文本编码

- mask：用输入图像1/4分辨率的mask，然后用$\left(2, 2\right)$卷积核，stride-2输出【共下采样16倍】，再用$\left(1, 1\right)$卷积核将channel升到256. mask 和image embedding通过element-wise相乘【可以理解成mask的feature对image的feature进行加权】

映射出的特征的channel和image embedding的channel一致【因为后面要用attention进行融合】。

## mask decoder

在prompt embeddings中插入一个可学习的token【iou token和mask token】，用于docoder的输出

<figure data-latex-placement="H">
<img src="/images/multimodal/SAM_maskdecoder.PNG" />
</figure>

- prompt toekns + output tokens进行self attn

- 用得到的token和image embedding进行 cross attn（token作为Q）

- point-wise MLP 更新token

- 用image embedding和（3）的token进行cross atten（image embedding作为Q）

重复上述步骤2次，再将attn再通过残差进行连接，最终输出masks和iou scores。

为了解决输出模糊性问题【一个提示可能生成多个mask】，预测输出多个masks，在训练过程中,只回传最小的loss，为了对mask进行排序，增加一个小的head预测mask和目标的iou。

当输入多个提示时，生成的mask会比较接近，为了减少loss退化和确保获取明确的mask，此时只预测一个mask

> masks的输出维度是$B\times C\times H\times W$，其中$B$是输入的prompt数量，$C$是mask的数量，$\left(H, W\right)$为输入图像尺寸

## 训练过程

- bbox预测分支：每个bbox的mask系数没有标签，故bbox head分支仅仅对bbox【$\left(N\times 4\right)$】和cls【$\left(N\times 81\right)$】分支计算loss，mask系数【$\left(N\times 32\right)$】监督信息来自后面的原型掩码预测分支

- 掩码预测分支：不能用预测的bbox来裁剪【**前期不稳定**】，基于正样本anchor，采用gt bbox去裁剪对应的预测mask图，就可以得到实例级别mask【直接采用所有gt bbox去crop，可能会存在bbox分支和protonet分支监督点不一致的问题】

  ```python
  prototypes = self.protonet(x) 
      prototypes = prototypes.permute(0, 2, 3, 1).contiguous() 
       
      # idx表示图片索引 
      cur_sampling_results = sampling_results[idx] 
      # 找出正样本索引 
      pos_assigned_gt_inds = cur_sampling_results.pos_assigned_gt_inds

      mask_pred = torch.sigmoid(mask_pred) 
       
      # 基于bbox裁剪出mask图 
      mask_pred = self.crop(mask_pred, bboxes_for_cropping)
  ```

## 推理过程

- 遍历每个预测输出层，对每个层先利用nms_pre参数过滤到指定数目的框；对这些框进行解码操作；最后对所有结果采用nms进行抑制得到指定数目的bbox和对应类别、mask系数值，默认最多是100

- 为了使得mask更加精确，这里只选择了FPN后输出的最大尺度特征图预测全局原型，特征图上面每个位置都采用长度为32的prototypes来表征，然后将N个预测框和 prototypes矩阵进行乘加操作，即可得到每个bbox对应的mask

- 利用bbox坐标去mask图上进行切割即可得到对应的mask图

- 二值化，插值函数将bbox和mask都还原到原始图尺度，最终得到实例分割结果

## 全实例分割

基于Yolov8-seg实现，可以参考YOLACT[15](YOLACT)

## 目标匹配

- 点提示：通过点提示匹配后，模型会选择与点提示相对应的多个掩码。然后，这些掩码会被合并成一个单一的掩码，以完整地标记感兴趣的对象。在合并过程中，可能会使用形态学操作（如膨胀和腐蚀）来改善掩码的合并效果

- 框提示：每个边界框与分割掩码之间的交并比，选择与用户指定的边界框具有最高IoU分数的分割掩码作为最佳匹配

- 文本提示：使用CLIP模型的文本编码器来处理文本提示，提取出与文本描述相对应的文本嵌入，再比较文本嵌入与图像特征之间的相似性，以找到与文本描述最匹配的图像区域

# Grounding DINO

**特点：**可以根据文字描述检测指定目标

相较于[8](GLIP)，它的优势是：

- Grounding DINO的transformer结构更接近于NLP模型，因此它更容易同时处理图片和文字

- Transformer-based detector在处理大型数据集时被证明有优势

- 作为DETR的变种，DINO能够完成end-to-end的训练，而且不需要NMS等额外的后处理

**越多越早的特征融合带来的收益越大**

在以上结论的指导下，作者设计了不同的特征融合方式分别应用在三个阶段上：

- 设计了结合self-attention、text-to-image cross-attention、image-to-text attention的特征enhancer应用在Neck中

- 设计了一个language-guided query selection方法用于初始化Head的query；

- 设计了一个跨模态的decoder用于Head部分，从而增强query的特征表达

Swin Transformer作为image backbone，BERT作为text backbone
